AI Function-Calling Router with
Injected Failure Recovery

A typed orchestration layer: NL requests → LLM tool selection → Pydantic validation → fault-injected execution → output-schema validation, with four distinct recovery policies (one per failure class), a strict retry bound of 1, and an explicit give-up — never a fabricated success.

Four failure classes, four distinct policies

Failure classHow it's provokedPolicyBound
missing_fieldrequest omits info ("Book a flight to Paris.")tiny re-prompt for only the missing field, merged + retried1 retry
type_errorloose phrasing ("tomorrow", "one hour", "five")re-prompt to translate the bad value into the required format1 retry
timeoutinjected TIMEOUTsystem backoff + direct Python retry — zero LLM tokens1 retry
schema_repairinjected MALFORMEDre-prompt to extract the corrupted payload into the output schema1 retry

After the bound the router returns exactly {"status": "error", "reason": "<failure_class>_unrecoverable"} — the explicit give-up.
